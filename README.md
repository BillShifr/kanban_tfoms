# Minimal Kanban

Self-hosted канбан для небольшой команды. PostgreSQL обязателен; файлы задач
хранятся отдельно на диске и резервируются вместе с базой.

## Локальный запуск

Самый короткий воспроизводимый путь:

```sh
docker compose up -d --build
```

После успешных healthchecks откройте `http://127.0.0.1:5173`. Локальная
тестовая учётная запись: `admin@example.com` / `change-me-now`. Эти реквизиты
разрешены только в development-окружении и запрещены production-конфигурацией.

Для разработки без контейнеров скопируйте `.env.example` в `.env`, выполните
`npm ci`, `npm run db:migrate`, затем `npm run dev`.

## Роли и видимость

- `Пользователь` работает со всеми сущностями продукта, но видит только доски,
  назначенные ему напрямую или через отдел.
- `Администратор` видит все доски и управляет обычными пользователями: создаёт,
  отключает, меняет пароль и выдаёт доступ к отделам и отдельным доскам.
- `Суперадминистратор` дополнительно создаёт администраторов и меняет роли.

При создании учётной записи и смене пароля администратор может сгенерировать
стойкий пароль: он показывается для проверки, сразу копируется и остаётся в
одноразовой карточке до закрытия окна.

Назначение отдела автоматически распространяется на его будущие доски. Роль
на уровне отдельной доски не даёт административных полномочий.

## Команда, достижения и профиль

Профиль открывается из меню пользователя справа в шапке.
Результаты закреплены в отдельной правой панели; на узком экране — в нижней
полосе с переходом к полной коллекции и рейтингу. Переключатель:
«Доступные доски» учитывает только доступные пользователю доски;
«Все сотрудники» показывает общий вклад активных сотрудников, включая нулевой.
Общий рейтинг не открывает доступ к чужим задачам и не возвращает их названия.
Показаны первые 20 участников и отдельная сводка текущего пользователя с его
местом. Равные баллы дают одинаковое место. Условия иллюстрированных достижений
открываются по нажатию. Месячные счётчики отделены от накопительных.
Компоновка, источники и спорные сценарии описаны в
[дизайн-документе](docs/design/team-achievements.md).

За новую задачу автор получает 2 балла, за первое завершение назначенный
исполнитель — 10. Завершение определяется последней активной колонкой доски.
Повторное закрытие не создаёт новое начисление; возврат в работу временно
исключает баллы завершения. Удалённые задачи и архивные доски не учитываются.
Без назначенной учётной записи баллы завершения не выдаются.
Рейтинг месячный (UTC), полученные достижения остаются в личной коллекции.
Восемь значков открываются за создание и завершение задач. Рамки аватара
выбираются в профиле или разделе «Рамки и награды». Три рамки выдаются за
завершения, ещё три — за призовые места общего месячного рейтинга.
Для сезонного приза нужно хотя бы одно завершение; равные баллы дают одинаковое
место. История наград сохраняется, а аура призёра действует следующий месяц.
Сезонный учёт начинается с обновления 0016, не задним числом.
Миграция `0019_backfill_task_contributions.sql` переносит существующие задачи
в журнал по их фактическим датам: создание засчитывается автору, а завершение —
назначенному исполнителю. Прошедшие сезоны при этом не пересчитываются.
Это сводка вклада, не оценка качества или производительности сотрудников.

Миграция `0015_team_progress.sql` добавляет журнал начислений и профили.
Начисления защищены от дублей уникальным ключом и триггером БД, в том числе
для старого API. Изменение ФИО в профиле не меняет роль.
Аватары PNG/JPEG/WebP преобразуются в JPEG 256×256; сервер ограничивает
размер 512 КиБ, не принимает SVG и хранит изображение в PostgreSQL.
Аватары включаются в обычную резервную копию БД.
Миграции `0016_rewards.sql` и `0017_reward_grant_concurrency.sql` добавляют
постоянную коллекцию, рамки и фиксацию сезонов. Закрытие сезона происходит
перед первым изменением данных в следующем месяце или при чтении рейтинга,
без отдельного cron. Новые начисления показываются коротким уведомлением;
перезагрузка и повторное закрытие не воспроизводят их заново.
Миграция `0019_backfill_task_contributions.sql` идемпотентна: уникальный ключ
не позволяет повторному деплою удвоить исторические начисления.

Карточки и колонки сворачиваются независимо; выбор сохраняется в браузере.
Свёрнутая колонка остаётся областью для переноса задач.

Новые комментарии отмечаются на карточке для автора и исполнителя задачи
на момент отправки; собственные сообщения не создают уведомлений.
После открытия обсуждения отметка прочтения сохраняется между устройствами.
Доска и открытое обсуждение обновляются каждые 15 секунд.
Миграция `0018_unread_comments.sql` не уведомляет о старых комментариях.

При проектировании использованы
[профили GitHub](https://docs.github.com/en/account-and-profile/concepts/personal-profile)
и [достижения GitLab](https://docs.gitlab.com/user/profile/achievements/):
личные вехи и понятные условия получения, без копирования их бейджей.
Иконки — [Lucide](https://lucide.dev/license), уже используемые приложением.
[Исследование достижений GitHub](https://arxiv.org/abs/2303.14702)
показывает неоднозначную реакцию пользователей и слабую связь бейджей
с качествами разработчиков. Поэтому баллы здесь не KPI и не оценка сотрудников:
нет штрафов за отсутствие ежедневной активности и баллов за количество комментариев.

## Проверки

```sh
npm run format:check
npm run typecheck
npm run lint
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

Production-требования, rootless Podman, собственный PostgreSQL, внутренний
HTTP, CI, pull-based автодеплой и проверенный backup/restore описаны в
`docs/operations.md`.

## Browser tests

Run the Compose stack first, then use `npm run test:e2e`. Playwright targets
`http://127.0.0.1:5173` by default; override it with `E2E_BASE_URL` for an
isolated test environment. Set `E2E_EMAIL` and `E2E_PASSWORD` to its bootstrap
account. The task-creation test creates a uniquely named board and deliberately
does not delete it, so it never removes user data.

Если на рабочей машине уже установлен Chrome, браузер можно не скачивать:
`E2E_BROWSER_CHANNEL=chrome npm run test:e2e`.
